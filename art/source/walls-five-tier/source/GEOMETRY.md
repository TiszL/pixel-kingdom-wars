# Crownkeep geometry study

This local renderer applies the accepted connection geometry to a five-tier timber-to-stone progression. Art studies guide materials; exact mating pixels come from the shared height field. No production atlas or gameplay code imports this renderer. The owner must review this local replacement before authorizing a separate production coding session.

`walls.mjs` uses tile spacing 32, bottom-center anchors `(x*32+16, (y+1)*32)` and frame sizes 32×44/48/52/56/60. `TIER_HEIGHTS` names the complete frame heights, not the physical face height. Intact walls paint in increasing footprint south-edge order; height never changes that order. A caller interleaving original buildings should use `drawWall(ctx, grid, x, y, {field: buildField(grid)})` at the same wall depth position as the game.

The grid is a `Map` keyed `"x,y"` with values `{tier:1|2|3|4|5, damage?:boolean, damageStage?:1|2}`. `resolveWall` preserves the production N/E/S/W bits 1/2/4/8 and outer-elbow naming. It additionally returns eight-neighbor context, filled quadrants, exposed sides, directional height differences, anchors and frame dimensions.

Cardinal arms have a shared 12px mating width. Chamfered junction piers widen to 24px. Fully adjoining 2×2 quadrants merge into a continuous surface; filled interiors carry neither internal outlines nor battlements. Repeated piers are suppressed along the perimeter of dense fills. All tiers share their foundation geometry. Diagonal-only neighbors cannot create arms or fill.

The higher-tier refinement replaces hard height jumps at tile boundaries with graded stone shoulders. Each tier retains its declared body height over an 8px central plateau. Moving toward a connected neighbor blends the body height across an 11px shoulder into a two-pixel shared collar. Both sides of every occupied mating edge therefore have exactly the same body and coping heights. Even the largest isolated T1↔T5 shoulder changes by at most one height pixel per footprint pixel. Top surfaces and exposed masonry risers follow that grade; battlements use a shared 16px cadence and never begin exactly at a tile boundary.

At dense corners the shoulder uses the connected component of four nearby tile centers. A three-cell concave corner shares one consistent transition surface, while a complete 2×2 blends all four tiers. An unconnected diagonal wall contributes no height. This additional diagonal context prevents mismatched corner shoulders without creating gameplay bridges. Removing a wall recomputes these local surface blends for the affected 3×3 neighborhood.

**Mixed-tier context has a larger envelope than lower-tier source art.** The 90-source local baseline uses 32×44/48/52/56/60 cell sizes for canonical uniform-tier arrangements. A lower-tier tile rising toward a higher northern neighbor can extend above its own source frame. `resolveWall().contextFrame` therefore explicitly reserves **32×60**, exposed as `CONTEXT_FRAME_HEIGHT`, for dynamic context rendering and capture. The horizontal footprint and bottom-center anchor remain unchanged. A future integration must render context overlays or larger contextual cells; cropping dynamic output to the lower-tier baseline frame would be incorrect.

The height field draws axis-aligned one-pixel rectangles. It shades top planes and south-facing exposed risers using consistent light from the upper left; it does not rotate master art. T1 has an 8px timber body with continuous plank decking, grain, capped posts, exposed braces and iron fasteners. T2–T5 have 12/16/20/24px stone bodies. Wood–stone metal collars appear only at exposed shared coping, never as internal boundaries in dense platforms. Warm limestone palettes, staggered stone courses, selective block highlights, lighter top mortar, pale corner quoins and restrained upper-tier brass/teal accents distinguish the levels. Surface damage introduces chips and cracks without deleting the connected foundation. Chips stop short of shared two-pixel collars so differing damage states cannot reopen a visual join. `damageStage:2` is visually distinct from stage 1.

Call `captureCollapse(grid,x,y,start)` before removing a wall. The snapshot freezes its actual geometry and pixel commands, including the then-current neighborhood. Remove the wall immediately and rebuild survivors. `drawCollapses(ctx,snapshots,time)` compresses the frozen wall into low timber splinters or stone rubble over `COLLAPSE_DURATION = 1000*4/12` milliseconds, matching four cells at 12fps. The caller decides how long finished rubble remains visible. Damage and collapse are purely visual and carry no gameplay numbers.

Run `node --test concepts/walls-2026-09-09/sandbox/geometry.test.mjs`. Seventeen checks cover all 256 eight-neighbor patterns, 6,480 center/cardinal tier configurations, 100 ordered directional tier joins, exact reciprocal mating pixels **and heights**, one-pixel shoulder grades, preservation of each tier's central height, dense center fill, diagonal-only separation, distinct local damage states, frozen collapse behavior, all 80 canonical frame bounds, the separate dynamic envelope, and no projected grass holes in damaged mixed-tier dense blocks. These are geometry and rendering invariants; visual acceptance remains separate.
