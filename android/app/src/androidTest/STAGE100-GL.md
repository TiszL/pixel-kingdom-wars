# Canonical Stage100 GL/lifecycle fixture

This instrumentation mode renders source-generated Stage100 SIM14 events through the production `SceneMapper`, `SceneSurface`, `KingdomFragment`, and `NativeGameRenderer`. The four fixtures contain 306 buildings, authoritative initial/max HP, 2/8/16/90 level-20 Dragons, and the original two hero deployments. `assets/battle-reliability/provenance.json` pins every fixture and its source inputs. The copied generator must run from the canonical source repository, where its relative imports resolve; do not run it from the Android asset directory or replace production content.

Build the normal app and separate test APK using the existing private HTTPS local-development configuration. Run only on the authorized `ranchu` emulator with the debug package and private/loopback origin on port 18443. No server is needed for this mode. Optimized-debug capture is intentionally rejected: its current `BuildConfig.DEBUG=false` makes the normal activity ignore offline preview. Do not remove this guard or use that activity to enter the retained account; an independent offline test host is required for future minified GL evidence. Do not clear app data, uninstall a package, edit device preferences, or install on a physical Seeker.

After the coordinator releases the emulator, run the existing runner with:

```sh
adb -s emulator-5554 shell am instrument -w -r -e mode stage100-gl gg.pixelkingdomwars.twa.debug.test/gg.pixelkingdomwars.nativeclient.LocalUiHarness
```

Use `-e orientation portrait` or `-e orientation landscape` to isolate a failed case; omission captures both. The landscape viewport must be less than 500dp high. Activity-local orientation is restored in `finally`; the harness does not write system rotation settings. Normal activity resume reapplies saved player orientation, so the fixture then reapplies only its temporary orientation override and waits for stable actual SurfaceView and renderer viewport dimensions, clearing old progress evidence. Each run writes a new `no_backup/stage100-gl/<epoch>/` directory. Preserve failed and successful receipts, PNGs, provenance, and `gl-frame-sampler.log` when collecting evidence through the existing `run-as` workflow. Do not delete old evidence to make a rerun pass.

A preliminary real GL probe renders Stage100 with both the performance sampler and remote diagnostics disabled. It requires a positive passive-observer texture estimate, then detaches and recreates the surface with performance sampling enabled. Rendered revision and observer state are cleared before recreation; a fresh callback must certify the new surface. The estimate covers AssetManager textures only and excludes direct ground, wall, font and stroke allocations; it is not total GPU memory. No stored diagnostic setting is changed.

Each orientation covers first activation, a deliberately invalid synthetic frame reference while the valid scene remains rendered, the normal recoverable error overlay and an explicit valid retry, task background/resume, Compose scene removal/return, dense playback, and rapid 2→8→16→90 replacements. The valid retry uses the same renderer update operation as `TRY AGAIN`; this is not a test of a physical tap. The invalid frame key exists only in the test's in-memory scene; the verified content directory is unchanged. The fixture uses the production theme/content colors without an overlapping test label. PNGs assert the actual pixel orientation, not just the requested configuration. SurfaceView PixelCopy captures the GL scene; Window PixelCopy captures window chrome and does not include the separate GL surface. Neither is a full display composite; inspect the paired retained-scene and overlay images rather than interpreting the window background as a vanished scene. Each screenshot receipt records `lastRenderedRevision`, `lastRenderedTick`, `eventEndTick` and `visualEndTick`; required first-pass screenshots also record and validate their intended tick bounds.

Allow about three to six minutes for both orientations. Each includes at least 65 active seconds. The first 90-Dragon pass runs uninterrupted at normal speed through the renderer's authoritative `visualEndTick`, without seeking or replacement. Required PNGs capture rendered tick windows 80–85, 130–135 and 220–225, the canonical event end (312 in this fixture), and the terminal visual endpoint. Missing a required window or stalling before the terminal tail fails within a bounded 45-second wait; the harness never fabricates progression. Later replays begin no sooner than 40 seconds after the previous activation. No combat simulation or gameplay command is executed by Android. The fixture graph requests no authentication, account data, HTTP, payments or orders. The existing offline-preview activity still initializes its ordinary application graph and reads device preferences; this harness neither enables diagnostic preferences nor changes existing report consent.

The passive observer records bounded renderer queue/wall-upload/viewport observations and actual `render()` CPU spans and intervals. Its lifetime is tied to the attached, resumed scene. Pending-work observations immediately preceding lifecycle actions are recorded separately: inspect `pendingObserved`, `lastObservedQueueDepth`, `lastObservedWallUploads` and `latestAlreadyRendered`; a fast already-committed replacement does not prove interruption during upload. No scheduling delay or private-field reflection creates overlap artificially.

`onFrame` records represent approximately 4Hz rendered-revision/playhead progress, not frame rate. UI Choreographer intervals are also labeled separately. The existing opt-in `PKWPerf` sampler supplies actual GL-loop reports after 60 active seconds; absence of such a report fails capture. Collection filters the exact process and run timestamp and bounds retained lines; it avoids `logcat -t`, which limits global history before tag filtering and can discard the relevant sample. The observer's CPU spans do not measure GPU completion or display presentation. Review per-orientation PNGs for retained old-scene continuity, terrain coverage, camera fit, complete wall/body/FX presentation, error recovery and coherent latest revision. Retain observed slow frames and failures; do not label them a physical-device result.

The September15 audio extension supplies the production NativeAudioBus, cue planner,
MediaExtractor decoder, mixer, Android audio focus and AudioTrack alongside the GL
workload. It generates a private hash-pinned **silent PCM** fixture with the source
cue-family names, not replacement production masters. It records actual decode,
output wake/close and peak voice counters and refuses success if only an ambience
voice was observed. Source files remain unchanged and no optional media download
occurs. This proves scheduling/driver integration; it does not certify sound-master
fidelity, production download/decode cost or physical Seeker performance. Previous
captures described below did not have a LocalNativeAudio provider and were audio-off.

A successful run is `captured-needs-visual-review`. It does not close physical Seeker ANR/performance acceptance, live-raid submission/recovery, wallet/payment checks, or Phase E. Those gates remain separate.
