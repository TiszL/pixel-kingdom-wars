# Realm engine: the web port's patches

The realm-map engine in this folder is the concept's `concepts/globe3d-2026-09-23/src/realm/` at **8acdf059**
(`globe-realms`). Its GLSL is locked to **02e9da84** (`globe-realms-veil`), the pin native uses
(`glsl.lock.json`; the twelve modules are byte-identical at both commits). Every change from the concept is listed
here. Anything not listed is verbatim, comments included, so the concept's comments still say `.js`,
`realm:lanes` and "demo" where they describe the concept.

Rename rule: `src/realm/X.js` became `X.mjs`, `glsl/X.glsl.js` became `glsl/X.glsl.mjs` (bytes unchanged), and
`X.test.mjs` became `X.cases.mjs`. Relative import specifiers follow the rename. `../../../../packages/shared/src/{constants,wallConnect}.ts`
became `@shardkeep/shared`. Left out: `dev.js` (lab page) and `demo-bases.js` (demo population). The latter is kept only
as the test fixture `demo-bases.fixture.mjs`, because `decor.cases.mjs` still exercises it; nothing shipped imports it.

Domes (D-181) are not an engine patch. `domes.mjs` decides each kingdom's `shield` bit: the feed's true always wins,
and the player's own base read only adds. The lane's existing `shieldBack`/`shieldFront` passes draw it.

Known gaps:
- No occupancy feed (OQ-1), so the counters and the minimap show only the kingdoms the viewport feed has returned.
- `ui.dispose()` (P11) is not exercised by a node test: `createUI` runs only after a realm pack has loaded, which the
  lifecycle stand-in never reaches. Its two removals are read in review; a SwiftShader leave-and-re-enter capture should
  count `getEventListeners(window).resize` once.
- `map.mjs` `reloadForUpdate` is kept verbatim. A lane chunk that fails to import (a deploy pruned it) reloads the page
  once a minute at most. The web's own reload prompt (4f5f1312) may be the better owner of that. Lane L6 decides.
