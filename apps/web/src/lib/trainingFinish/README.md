# Paid Training Finish All recovery foundation

Connected through `useTrainingFinish`, `TrainingFinishProvider` and the Army/Bases entry points. The free first-training journal/wire remains separate and unchanged. Focused gates and review status are recorded in the training handoff; full combined acceptance is parent-owned.

`TrainingFinishJournalStore` uses one strict IndexedDB record per canonical page origin/API/cluster/wallet, independent of other paid groups and the free onboarding journal. Original key, base, queue rows, ceiling and chosen KEEP/GEMS currency are immutable. The append-only archive permanently reserves keys. IndexedDB CAS and per-identity Web Locks protect cross-tab attempts; storage and lock unavailability fail closed.

The browser fetches authenticated `/me`, owned `/bases`, `/army` and `/balances`, then brackets identity/ownership again. New review requires current v2 sequential scheduling, version1 training receipts, exact spend support, a complete matching server quote, and an explicitly selected active owned base. It chooses whole Gems when sufficient, otherwise whole custodial KEEP, never pooled balances. `freeFinishAllOffer !== null` or missing/ambiguous free eligibility blocks paid review. The hook additionally blocks paid begin/review/confirm while the existing free journal is pending or corrupt; this module neither reads nor alters that journal.

`begin` probes the receipt protocol before atomically saving original intent and any matching accepted preflight evidence. No POST occurs. `confirm` requires current ephemeral review, repeats GET proof/fresh validation, durably marks the original attempt, and sends exact body plus request-local currency header. A current unchanged subset/lower quote can validate, but the persisted full original queue/ceiling never changes. Only the server proves whether omitted rows naturally completed or were cancelled. New/rescheduled rows and higher prices refuse locally. No browser-clock repricing.

Mount/foreground `open` is GET-only. Explicit `reviewCommand` followed by `confirm` is the only retry, using the same key/body/currency. Unknown, unauthenticated, network failures and malformed proof retain the original pending command. GET lookup uses original key/base, then shared proof validation matches the complete original request, wallet and funding. Receipt history does not depend on today's selected base or affordability. A rejected/missing later GET cannot erase already stored acceptance.

Only the exact first-POST allowlist in `journal.ts` can persist refusal. Currency refusal also requires matching expected-currency details. The API observer preserves refusal under the captured original CAS revision before navigation/session rejection; K161 `postRaw` drains its original transport/evidence callback before settling. Retry/GET failures, generic404, malformed responses and receipt/idempotency collision codes are not terminal proof. `TRAINING_NOT_RUNNING` is404 only; quote/scope/claim changes are409. A refused record may archive after a fresh matching unknown receipt; a never-attempted draft may explicitly archive with the same proof. An ambiguous attempt cannot be abandoned.

UI integration invariants:

- Bind real current session, visibility/navigation epoch, mutation allowance and synchronous mutationGate. Call `dismiss()` on back/background, base selection or live action-gate closure. It invalidates ephemeral approval, not durable intent. Keep a captured original store alive until all outstanding action promises/evidence writes drain; do not close IDB during response parsing.
- Keep history reachable when paid actions pause or the original base is sold/unselected. Never auto-POST on mount or automatically create a replacement key.
- Show original full queue/base, maximum charge and actual chosen currency; show accepted funding/result as history. Free `first_troops` keeps its existing separate behavior.
- Use `refreshTrainingFinishSnapshot` for current base/army/balances only. It brackets fresh authority, checks matching roster counts/levels, and uses selected-base epoch/latest-read snapshot commit. Receipt completion is never a HUD patch. An unavailable base returns no snapshot without substitution. The hook separately captures its request/payment/base revision and rechecks it before publishing the returned local army state; the helper only atomically commits global base and balances.
- New paid admission is deliberately explicit-base only, matching Research. Nullable legacy historical intents remain readable; no legacy new-payment UI is supplied here.
